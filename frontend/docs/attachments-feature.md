# Прикрепление файлов к паре — как это устроено на фронтенде

Документ описывает, как преподаватель прикрепляет файлы к конкретной паре, как студенты их видят и скачивают, и какие запросы при этом уходят на сервер. Написано простым языком — чтобы понять общую картину, не нужно быть программистом.

---

## 1. Где пользователь видит эту фичу

В правой части экрана с расписанием находится боковая панель «Заметки». Когда пользователь кликает по паре в расписании, в этой панели появляются два раздела:

1. **Заметка** — личная заметка пользователя (видна только ему).
2. **Материал** — публичный материал от преподавателя. Именно сюда прикрепляются файлы.

Файл «прикрепляется» к конкретной паре в конкретный день (например, «Математика, 25 мая 2026»), а не ко всему предмету в целом.

Файл за всю реализацию панели заметок отвечает:
[NotesPanel.tsx](frontend/src/widgets/notes-panel/NotesPanel.tsx)

Сами файлы (загрузка, превью, удаление) вынесены в отдельный компонент:
[AttachmentsList.tsx](frontend/src/widgets/notes-panel/AttachmentsList.tsx)

`NotesPanel` подключает `AttachmentsList` внутри раздела «Материал» и передаёт ему три параметра:
- `scheduleItemId` — id выбранной пары,
- `lessonDate` — дата пары,
- `canEdit` — может ли текущий пользователь добавлять/удалять файлы (true для преподавателей, false для студентов).

См. [NotesPanel.tsx:185-191](frontend/src/widgets/notes-panel/NotesPanel.tsx#L185-L191).

---

## 2. Что видит пользователь в зависимости от роли

### Преподаватель (`canEdit = true`)
- Видит список уже прикреплённых файлов.
- Под списком — кнопка с пунктирной рамкой **«Прикрепить файл»** со значком скрепки.
- Рядом с каждым файлом есть иконки **скачать** и **удалить** (корзина).

### Студент (`canEdit = false`)
- Видит только список файлов и иконку **скачать**.
- Кнопки «Прикрепить» и «Удалить» не отображаются.
- Если файлов нет вообще — раздел не показывается совсем (см. [AttachmentsList.tsx:91](frontend/src/widgets/notes-panel/AttachmentsList.tsx#L91)).

## 3. Как выглядит «превью» одного файла

Один файл в списке (компонент `AttachmentRow` внутри [AttachmentsList.tsx:21-62](frontend/src/widgets/notes-panel/AttachmentsList.tsx#L21-L62)) — это горизонтальная строка-карточка, в которой по порядку:

1. **Иконка скрепки** (lucide-react `Paperclip`).
2. **Название файла** — кликабельная ссылка. Клик открывает файл в новой вкладке (скачивание). Длинное имя обрезается многоточием.
3. **Размер файла** — человекочитаемо: «512 Б», «23.4 КБ», «1.2 МБ». За форматирование отвечает функция `formatSize` ([строки 15-19](frontend/src/widgets/notes-panel/AttachmentsList.tsx#L15-L19)).
4. **Иконка «Скачать»** (`Download`) — дублирует клик по имени.
5. **Иконка «Корзина»** (`Trash2`) — только для преподавателя. При клике показывает обычный браузерный `confirm` «Удалить файл …?». Если пользователь подтвердил — файл удаляется.

Никакого «настоящего» превью содержимого (картинка, превью PDF) **нет** — фронтенд показывает только имя, размер и иконку скрепки. Открытие файла — это просто ссылка на сервер, который отдаёт файл.

## 4. Кнопка «Прикрепить файл» — как работает выбор файла

Сама кнопка — это `<button>` ([AttachmentsList.tsx:113-122](frontend/src/widgets/notes-panel/AttachmentsList.tsx#L113-L122)). Рядом находится **скрытое** поле `<input type="file" multiple>` ([строки 106-112](frontend/src/widgets/notes-panel/AttachmentsList.tsx#L106-L112)).

Логика проста:
1. Пользователь кликает по красивой кнопке «Прикрепить файл».
2. Внутри обработчика клика мы программно «кликаем» по скрытому `<input>` через ref (`fileInputRef.current?.click()`).
3. Открывается стандартный системный диалог выбора файлов.
4. Когда пользователь выбрал один или несколько файлов, срабатывает `onChange` инпута и вызывается функция `handleFiles`.

Атрибут `multiple` у инпута означает, что можно выбрать сразу несколько файлов за раз.

### Что делает `handleFiles`
([AttachmentsList.tsx:70-83](frontend/src/widgets/notes-panel/AttachmentsList.tsx#L70-L83))

1. Берёт все выбранные файлы.
2. Загружает их **по одному, последовательно** (`for ... await upload.mutateAsync(file)`).
3. Если какой-то файл не загрузился — показывает alert «Не удалось загрузить …».
4. После всех загрузок очищает значение инпута — чтобы можно было выбрать тот же файл ещё раз и снова сработал `onChange`.

Пока идёт загрузка, кнопка показывает текст «Загрузка…» и становится неактивной (`disabled`). За это отвечает флаг `upload.isPending`.

## 5. Запросы к API

Все запросы про файлы собраны в одном файле:
[attachments.ts](frontend/src/shared/api/attachments.ts)

Базовый URL берётся из конфига: [src/shared/config/index.ts](frontend/src/shared/config/index.ts). Аутентификация — JWT в HttpOnly cookie, поэтому во всех запросах стоит `credentials: "include"` (браузер автоматически прикладывает cookie).

| Что происходит        | Метод  | Адрес                                          | Описание                                                  |
| --------------------- | ------ | ---------------------------------------------- | --------------------------------------------------------- |
| Получить список файлов | GET    | `/api/attachments?schedule_item_id=…&lesson_date=…` | Возвращает массив файлов, прикреплённых к этой паре в эту дату |
| Загрузить файл        | POST   | `/api/attachments`                             | Отправляется `multipart/form-data` с тремя полями: `schedule_item_id`, `lesson_date`, `file` |
| Удалить файл          | DELETE | `/api/attachments/{id}`                        | Удаляет файл по его id                                    |
| Скачать файл          | GET    | `/api/attachments/{id}/download`               | Не вызывается из кода — это просто URL, который вставляется в `href` ссылки |

Тип объекта, который возвращает сервер для одного файла (`AttachmentOut`), описан в [types.ts:130-139](frontend/src/shared/api/types.ts#L130-L139):

```
id, schedule_item_id, lesson_date, teacher_id,
original_filename, content_type, size, created_at
```

Если запрос упал — функция `parseDetail` ([attachments.ts:6-23](frontend/src/shared/api/attachments.ts#L6-L23)) пытается аккуратно достать сообщение об ошибке из ответа сервера, чтобы показать его пользователю.

## 6. Где хранится состояние

На проекте принято правило (см. [frontend/CLAUDE.md](frontend/CLAUDE.md#L126-L131)):

- **Локальное UI-состояние** (открыта ли модалка, что выбрано) — в Zustand или внутри React-компонента.
- **Серверные данные** (списки, сами файлы) — **никогда не дублируются** в Zustand. Их хранит **TanStack Query** — это библиотека, которая сама кэширует ответы сервера, обновляет их и следит за актуальностью.

### Конкретно для файлов

Все «обёртки» для запросов лежат в:
[entities/attachments/model/queries.ts](frontend/src/entities/attachments/model/queries.ts)

Публичный API сущности (что разрешено импортировать снаружи):
[entities/attachments/index.ts](frontend/src/entities/attachments/index.ts)

Там определены три React-хука и один «ключ кэша»:

1. **`attachmentsKeys.list(scheduleItemId, lessonDate)`**
   Это «адрес в кэше». Простой массив-идентификатор: `["attachments", "list", 42, "2026-05-25"]`. По нему TanStack Query понимает, какой именно список файлов мы запрашиваем. Для разных пар и дат — разные кэши.

2. **`useAttachments(scheduleItemId, lessonDate)`** — загружает список файлов.
   - Запрос уходит, только если оба параметра заданы (`enabled: …`).
   - Данные считаются «свежими» 30 секунд (`staleTime: 30_000`) — в течение этого времени повторно сервер не дёргается.

3. **`useUploadAttachment(scheduleItemId, lessonDate)`** — мутация для загрузки файла.
   После успешной загрузки **инвалидирует** кэш списка (`qc.invalidateQueries(...)`) — то есть говорит «эти данные устарели, перезапроси с сервера». В итоге список автоматически обновляется и новый файл появляется в UI.

4. **`useDeleteAttachment(scheduleItemId, lessonDate)`** — мутация для удаления. Логика та же: после успешного DELETE инвалидирует кэш списка.

### Что это даёт на практике

- Не нужно вручную «добавить файл в массив в стейте» или «убрать его из массива».
- После загрузки/удаления список перерисовывается сам.
- Если открыть ту же пару повторно в течение 30 секунд — список покажется мгновенно из кэша, без запроса.
- Один и тот же список, открытый в двух местах интерфейса, всегда одинаковый — данные приходят из одного кэша.

## 7. Полный путь «прикрепил файл → файл появился у студентов»

Шаг за шагом:

1. Преподаватель кликнул по паре в расписании → `NotesPanel` получил `selectedItem` и `selectedDate`.
2. Внутри отрисовался `AttachmentsList` с `canEdit = true`.
3. Хук `useAttachments` отправил `GET /api/attachments?schedule_item_id=…&lesson_date=…` и показал список.
4. Преподаватель нажал «Прикрепить файл» → открылся системный диалог → выбрал файл.
5. `handleFiles` вызвал `upload.mutateAsync(file)` → `attachmentsApi.upload` отправил `POST /api/attachments` с FormData.
6. После успеха TanStack Query инвалидировал кэш списка → автоматически уехал новый `GET` → список обновился, файл появился в UI.
7. Студент в это время (или при следующем открытии этой пары) делает свой `GET /api/attachments?...` → получает уже обновлённый список → видит файл со ссылкой на скачивание.
8. По клику на имя/иконку «Скачать» браузер просто открывает `GET /api/attachments/{id}/download` — сервер отдаёт сам файл.
